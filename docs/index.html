SpryCSS

SpryCSS

SpryCSS aims to be a simple, lightweight and dependency free CSS Toolkit, but can be customized with a sass compiler if needed.
The goal is to remove the messy and tedious task of coming up with class names for elements that just need simple layout styles and provide basic components to help you get up and running fast, but not try to do everything which can bloat your project.
It is almost inevitable that you will need to add your own custom css and therefore it should be simple and easy to do without conflicts. SpryCSS does not use !important and tries to use the lease amount of css priority as possible.

SpryJS Javascript Optional

SpryCSS is meant to be quick and easy to implement without needing to add any dependencies or javascript. However, there are times when you need more functionality. You can use your own Javascript or any Javascript framework you like. You can also use SpryJS which works well with SpryCSS for additional functionality like Navigable, Observe, Parallax, ScrollSpy, Sliders, Toggles, Cookies, Hash, and Query.

SpryCSS also comes with basic css only Sliders and Toggles that have limited functionality, but you can use SpryJS to extend them.

Breakpoints

SpryCSS is mobile first. Meaning all styles start from the smallest device then allow for changes with min-width using breakpoints.
By default, SpryCSS only comes with one breakpoint md at 40em.

You can add more breakpoints in the SCSS Variables, but keep in mind that the more breakpoints you add the larger the compiled file size will be.

SCSS Variable

// Specify each breakpoint size // Adding breakpoints will increase bundle size so add cautiously. $breakpoints: ( md: 40em, // lg: 80em, );

Media Queries

To use media queries use the prefix {breakpoint}: with allowed component classes. See below for which components and utilities use breakpoints.

<div class="p-4 md:p-2">

Container Queries

To use container queries use the prefix @{breakpoint}: with allowed component classes. See below for which components and utilities use breakpoints.

Container queries require a wrapping element that has container-type: inline-size;. You can use the class @container to add this to a parent element.

<div class="@container"> <div class="p-4 @md:p-2"></div> </div>

Containers with container-type: inline-size; will break the position of any child elements. This will break modals and other elements if placed inside. If this is not desired then you will need to place those elements outside the container element.

Gaps

Default gaps (aka gutters) are automatically adjusted based on your breakpoints. If you add more breakpoints in your SCSS Variables you will also need to add the corresponding Gap.

SCSS Variable

// Specify each breakpoint gap size. // <section> tags with get padding based on gap size. // * You must include one for each Breakpoint otherwise it will result in a Compile Error. $gaps: ( default: 1.25em, // required md : 2em, // lg: 2.25em, );
* You need to make sure the gaps match the breakpoints otherwise you will receive a SCSS compile error.

Icons

SpryCSS doesn't come with its own icon package. You can use whatever icon package or icon webfont you want, but icon web-fonts can greatly increase the size of your projects. A recommended alternative is to use direct svg code within your project. This produces the smallest file size while producing high resolution icons and allowing you the most flexibility to style the icons within your css.

A great option for this is Material Design Icons or Material Design Icons Light. You can search for icons and view the SVG code by clicking on the Code dropdown and click on 'View SVG'. Then copy and paste the code in your html.

If your using Visual Studio Code you can install the extension vscode-materialdesignicons-svg that provides code snippets to quickly add the SVG code.
